# Lab2 分支任务：三分钟交互式演示

本稿把 Leader 的 Task 07 批处理步骤改成交互命令。历史实测值来自 `evidence/t7_paged_qemu_gdb.txt`、`t7_bare_qemu_gdb.txt`；命令尚待本人按三终端练习，不声称本稿重新执行过。主线演示约三分钟，准备和补充对照不计入。答辩现场自己解释，不需要调用大模型。

## 准备：启动三个终端

三个终端都先进入课程目录：

```sh
cd /Users/wesley/大三上课程/操作系统
```

终端1：

```sh
./os2026.sh debug
```

说明：“QEMU 在容器内启动，`-S` 先暂停客户机，`-s` 开放1234调试端口。”保持这个终端运行。镜像已有带调试信息的 QEMU 4.1.1，不需重新编译或 sudo。

终端2：

```sh
./os2026.sh gdb-qemu
```

接下来的命令输入终端2的 **宿主 gdb**：

```gdb
set pagination off
handle SIGPIPE nostop noprint
set $va = 0xffffffffc0207008
tbreak target/riscv/cpu_helper.c:451 if address == $va && access_type == 0
continue
```

这里先断在真实的 `riscv_cpu_tlb_fill` 调用内部，而不是直接断所有 `get_physical_address` 调用。gdb 读内存走 `cpu_memory_rw_debug → debug翻译`，不经过此 fill，所以不会被误认成客户机 load。`access_type=0` 是数据读，避免把取指当作 load。依据：QEMU `cpu_helper.c:382-389,451`、`exec.c:3964-3990`，Task07 [A] 栈。

终端3：

```sh
./os2026.sh gdb
```

接下来的命令输入终端3的 **客户机 gdb**：

```gdb
set pagination off
set remotetimeout unlimited
p/x (((unsigned long long)&end + 4095) & ~4095ULL) + 8
p/x &kern_init
continue
```

第一项是在本次 ELF 中计算描述符首页 flags 的虚拟地址，不读该页内容。历史值为 `0xffffffffc0207008`；kern_init 历史值为 `0xffffffffc02000d6`。不是 `&pages`，后者是保存数组指针的全局变量自身地址。若第一项不同，在客户机 continue **之前**先回终端2按 Ctrl-C，`set $va = 新值`，再 `continue`；条件使用变量，自动采用新值。也可事先用容器中的 `riscv64-unknown-elf-nm -n /code/bin/kernel` 找 end、kern_init、boot_page_table_sv39，用 `riscv64-unknown-elf-objdump -d -S /code/bin/kernel` 核对具体 ld/sd。地址随编译变化，以当前 ELF 为准。本稿 `pmm.c:97-98` 是 Task 07 取证时行号，后续扩展插入代码后按 `SetPageReserved` 语句定位。

终端2出现停点后，终端3的 continue 还在等待是正常现象。之后只在终端2单步，结束时先恢复终端2，终端3才会响应。

## 主线：按六次停点讲清一次读取

### 0:00—0:30，停点 A：确定是真的数据 load

终端2：

```gdb
bt 6
p/x address
p access_type
p mmu_idx
p/x env->satp
p env->priv
step
bt 7
```

`step` 从451行调用进入 `get_physical_address`；若先停在其他源码行，查看 `frame`，继续 step 到该函数入口再讲。历史值：`address=0xffffffffc0207008`、`access_type=0`、`mmu_idx=1`、`satp=0x8000000000080205`、`priv=1`。栈应含 `riscv_cpu_tlb_fill → tlb_fill → load_helper → helper_le_ldq_mmu → code_gen_buffer`，没有 `cpu_memory_rw_debug`。若存在 debug 栈，丢弃本样本，不把它当实际指令。

一句话：“这次是 S 态内核读 `pages[0].flags`，软件 TLB 未命中，因此进入地址翻译。”依据：Task07 [A]，`pmm.c:97-98` 与 `memlayout.h:45`。

### 0:30—1:15，停点 B：看物理页表和叶子

终端2：

```gdb
tbreak target/riscv/cpu_helper.c:254 if addr == $va
continue
p levels
p ptidxbits
p ptesize
p i
p ptshift
p/x base
p idx
p/x pte_addr
p/x pte
next
p/x ppn
p/x pte & 0xff
```

历史值为 `3,9,8,0,18`；`base=0x80205000`、`idx=511`、`pte_addr=0x80205ff8`、`pte=0x200000cf`、`ppn=0x80000`、低位`0xcf`。254行先计算 ppn，因此要 next 后再打印它。

一句话：“satp 的 PPN 左移12位给出根表；索引511乘8找到 PTE。R/X 为1说明它已经是1GB叶子，所以这次只查一层，不是少调了两层。”依据：Task07 [B]，`cpu_helper.c:184-191,237-278`。

### 1:15—1:45，停点 C：得到客户机物理地址

```gdb
tbreak target/riscv/cpu_helper.c:334 if addr == $va
continue
p/x vpn
p/x ppn
p ptshift
next
p/x *physical
p/x *physical + ($va & 0xfff)
```

历史值：`vpn=0xffffffffc0207`、`ppn=0x80000`、`ptshift=18`，物理页基址=`0x80207000`，加偏移8得到=`0x80207008`。

一句话：“大页保留 VA 的低18位页号，函数返回4KB物理页基址；还要加8才是本次数据的完整物理地址。”依据：Task07 [C]，`cpu_helper.c:333-334`。

### 1:45—2:10，停点 D/E：返回并装入软件 TLB

```gdb
finish
p/x pa
p prot
next
p ret
tbreak tlb_set_page_with_attrs if vaddr == ($va & ~0xfffULL)
continue
p/x vaddr
p/x paddr
p prot
p mmu_idx
p/x size
```

`finish` 显示函数返回0。Task07 [D] 的 ret=1 是赋值前旧值，不能说翻译失败；next 执行赋值后再看 ret。历史装表值：`vaddr=0xffffffffc0207000`、`paddr=0x80207000`、`prot=7`、`mmu_idx=1`、`size=0x1000`。

一句话：“翻译成功，权限是读写执行。虽然页表映射1GB，QEMU 这次只缓存一个4KB软件表项。”依据：Task07 [D][E]，`cpu_helper.c:471-473`。

### 2:10—2:45，停点 F：最后读的是宿主内存

```gdb
tbreak accel/tcg/cputlb.c:1338 if addr == $va && !code_read
continue
p/x entry->addr_read
p/x entry->addend
next
p/x haddr
x/gx haddr
```

历史 tag=`0xffffffffc0207000`、addend=`0xffffafe00000`、haddr=`0xffff70007008`，该8字节值为0。宿主地址和 addend 随进程变化，不要求与日志一模一样；应核对64位加法 `VA+addend=haddr`。

一句话：“QEMU 还要把客户机物理内存定位到宿主 RAM；软件 TLB 的 addend 让后续访问直接算出宿主指针。”此处 `x/gx` 是宿主 gdb 读宿主指针，不是终端3读客户机 VA。依据：Task07 [F]，`cputlb.c:804,1338-1361`。

### 2:45—3:00，收尾

```gdb
continue
```

一句话：“之后同页访问可以直接在生成代码中命中 TLB，不再进入这个 C helper。Bare 模式也使用 QEMU 软件 TLB，但地址翻译函数直接返回原地址。”同页快路径结论来自 Task07 [G] 的未再停点记录与源码，不声称现场打印过一段 [G] 命中输出。此时内核最后会循环，gdb不自动退出；结束演示可在终端2 Ctrl-C 后 `detach`、`quit`，再停止终端1的调试运行。

## 常见问题

- 出现 `Ignoring packet error`：在终端3输入 `set remotetimeout unlimited` 后重试；若正在等终端2停点，先继续终端2，超时设置不会自动恢复被暂停的 QEMU。
- 容器名冲突：先 `docker ps -a --filter name=os` 核对。仅当确认 `os` 是可停止的旧调试容器时，执行 `docker rm -f os`，再重开；该命令会强制停止并删除该容器。正常结束上一轮优先退出对应调试会话。
- 断点不命中：先核对目标地址、satp模式和是否已经错过首次访问；自然 TLB 命中不走 fill。重新启动捕获首次访问，不要靠反复 continue 保证 miss。若 `load_helper` 无符号，改用 `cputlb.c:1271/1338` 或 `helper_le_ldq_mmu`，这些源码行可能有多个位置，要加地址条件。不要把无命中自行写成成功。
- `step` 没停到预期函数：`frame`/`list` 看当前位置，`info break` 检查行号映射。`ret/ppn/haddr` 等变量必须在赋值后才读；不得用未初始化值解释结果。
- 主机指针变化：正常，只验证 VA、PA和宿主指针之间的关系；固定历史addend不是验收条件。遇到 debug栈丢弃样本，继续等真实fill。

## 助教可能问的10个问题

1. **两个 gdb 分别调谁？** 终端2 attach QEMU进程，调模拟器源码；终端3连接stub，调ucore。
2. **这次是取指还是读数据？** 数据load，access_type=0、size=8，目标是描述符flags，栈含ldq helper。
3. **satp怎么得到根表？** MODE=8是Sv39，PPN=0x80205，左移12得到0x80205000。
4. **为什么只查一层？** 根项就是1GB叶子；4KB映射需要前两层是有效非叶子，再查第三层。
5. **PTE为什么不是虚拟地址读取？** pte_addr是客户机物理地址，源码用ldq_phys读取，不递归执行Sv39。
6. **0x80207000和0x80207008哪个正确？** 前者是函数返回的4KB页基址，后者是加偏移后的本次完整PA。
7. **addend是PA减VA吗？** 不是，它把客户机VA变成宿主RAM指针；这次宿主地址按实际进程变化。
8. **未分页为何也有TLB？** QEMU仍需缓存客户机地址到宿主内存的定位，Bare翻译直接PA=addr；真实CPU Bare不做分页翻译，未实测其微架构。
9. **写satp后低地址为何没立即缺页？** 4.1.1旧代码TLB项命中；ASID不变时write_satp未显式flush，后续同TB内执行sfence并跳高地址。8.2.2解释仍是推测。
10. **为什么同页读看不到C断点？** TCG生成代码可以直接命中软件快表；gdb调试读又可能反过来触发翻译，所以还要核对调用栈，不能只看地址。

所有要点均对应报告分支任务1～6问及其中的源码和evidence引用；A/D更新、victim命中、真实芯片缓存组织及异常sw反汇编原因没有动态验证，不作额外结论。
